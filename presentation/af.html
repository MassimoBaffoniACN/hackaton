1Executive Summary

Il problema: Le bollette italiane (Enel, Eni, INPS) sono documenti da 3-5 pagine pieni di tabelle, acronimi e numeri. Per milioni di italiani — anziani, persone con disabilità visive, persone con ADHD, stranieri — questi documenti sono incomprensibili. Il risultato è ritardi di pagamento, errori, stress e dipendenza da famigliari o call-center.
La soluzione: BollettaChiara è una web app che trasforma qualsiasi bolletta in una scheda semplice con 4 informazioni essenziali (importo, scadenza, come pagare, cosa fare), accessibile a tutti e funzionante senza connessione dopo il caricamento. Zero backend. Zero dati inviati a server. Privacy garantita.

4Requisiti di Accessibilità

Derivati direttamente dai 6 profili persona. Standard di riferimento: WCAG 2.2 livello AA.

4.1 Screen reader (Raffaele)

  • HTML semantico: <main>, <section>, <h1>…<h3>, <nav>, <button> nativi
  • ARIA live region aria-live="polite" sul container dello stato OCR: l'utente sente l'aggiornamento senza perdere il focus
  • Focus management: dopo upload, focus si sposta sul progress bar; dopo elaborazione, focus va al titolo della scheda risultati
  • Tutti i controlli hanno aria-label descrittivo
  • Nessuna interazione mouse-only (niente drag-and-drop senza fallback tastiera)
  • Ordine del DOM = ordine logico di lettura

4.2 Ipovedenti (Cecilia)

  • Font body: minimo 20px; importo: 40px; scadenza: 24px
  • Contrasto colore: ≥ 4.5:1 per testo normale, ≥ 3:1 per testo grande (WCAG AA)
  • Layout fluido: nessun overflow:hidden che tronchi il testo in zoom
  • Toggle "Alto contrasto" nel header: inverte palette su dark su bianco-su-nero
  • Input di upload: dimensioni target click minimo 44×44px (WCAG 2.5.5)

4.3 ADHD (Marco)

  • Nessuna animazione autmatica che parta al caricamento (prefers-reduced-motion rispettato)
  • Stato di elaborazione: progress bar lineare con percentuale, non spinner infiniti
  • Call-to-action principale: un solo pulsante prominente per azione (non 5 bottoni paritetici)
  • Countdown scadenza visivamente prioritizzato

4.4 Dislessia (Laura)

  • Font: Segoe UI / system-ui di default; toggle OpenDyslexic disponibile
  • letter-spacing: 0.05em, line-height: 1.65 nel body
  • Importi: formato € 127,40 (spazio dopo simbolo, virgola decimale italiana)
  • Nessun testo giustificato (solo text-align: left)

4.5 Plain language (Ahmed)

  • Frasi nella scheda risultati: massimo 15 parole
  • Termini tecnici obbligatori (es. "POD", "PDR") sempre seguiti da una spiegazione tra parentesi
  • Metodi di pagamento: sempre icona + etichetta (non solo icona, non solo testo)

Flusso dati dettagliato

  1. File input: l'utente seleziona o trascina PDF/immagine nel browser
  2. Routing di estrazione:
    • PDF con testo nativo → PDF.js estrae testo direttamente (veloce, <1s)
    • PDF scansionato / immagine → Tesseract.js esegue OCR (5-15 secondi)
  3. BillParserService: riceve stringa di testo grezzo, applica pattern regex ordinati per priorità, restituisce oggetto BillData
  4. BillSummaryComponent: renderizza la scheda usando i segnali Angular dalla store
  5. [Step 2] ClaudeService: costruisce il prompt, chiama l'API in streaming, emette token progressivamente via Observable<string>

Modello dati BillData

interface BillData {
  // Campi obbligatori (Step 1)
  amount:          number | null;    // importo in EUR
  dueDate:         Date   | null;    // data scadenza pagamento
  dueDaysLeft:     number | null;    // giorni rimanenti (calcolato)
  paymentMethods:  PaymentMethod[];  // metodi di pagamento rilevati
  supplier:        string | null;    // fornitore: ENEL, ENI, INPS…
  billType:        BillType;         // ELECTRICITY | GAS | WATER | OTHER
  customerCode:    string | null;    // codice cliente
  pod:             string | null;    // POD (elettricità)
  pdr:             string | null;    // PDR (gas)
  rawText:         string;           // testo grezzo per Step 2

  // Confidenza parsing
  confidence:      'high' | 'medium' | 'low';
  missingFields:   string[];         // campi non trovati
}

9Pattern Regex per Bollette Italiane

I pattern sono applicati in cascata, del più specifico al più generico. In caso di match multipli, si usa l'importo più alto (di solito è il totale) o si prende quello esplicitamente etichettato come "totale".

9.1 Importo da pagare

// Priorità 1 — etichette esplicite "totale da pagare"
/(?:totale\s+da\s+pagare|importo\s+da\s+pagare|saldo\s+dovuto)[^\d€]*€?\s*(\d{1,4}[.,]\d{2})/gi

// Priorità 2 — "importo" generico
/(?:importo|totale\s+fattura|totale\s+bolletta)[^\d€]*€?\s*(\d{1,4}[.,]\d{2})/gi

// Priorità 3 — "da pagare" senza "totale"
/da\s+pagare[^\d€]*€?\s*(\d{1,4}[.,]\d{2})/gi

// Normalizzazione: "127.456,78" → 127456.78 | "127,78" → 127.78

9.2 Data di scadenza

// Formato GG/MM/AAAA o GG-MM-AAAA o GG.MM.AAAA
/(?:scadenza|entro\s+il|pagare\s+entro|data\s+limite)[^\d]*(\d{1,2}[\/\-\.]\d{1,2}[\/\-\.]\d{2,4})/gi

// Formato testuale: "entro il 30 settembre 2026"
/entro\s+il\s+(\d{1,2})\s+(gennaio|febbraio|marzo|aprile|maggio|giugno|luglio|agosto|settembre|ottobre|novembre|dicembre)\s+(\d{4})/gi

9.3 Identificativi utente

// Codice cliente (8-12 cifre)
/(?:codice\s+cliente|cod\.?\s*cliente|n\.?\s*cliente)[^\d]*(\d{7,12})/gi

// POD (punto di prelievo elettricità) — formato europeo IT + 14 cifre
/\bPOD[:\s]*([A-Z]{2}\d{14})\b/gi

// PDR (punto di riconsegna gas) — 14 cifre
/\bPDR[:\s]*(\d{14})\b/gi

// Codice fiscale intestatario (fallback nome)
/(?:intestato\s+a|titolare)[:\s]+([A-ZÀÈÉÌÒÙ][a-zàèéìòù]+(?:\s+[A-ZÀÈÉÌÒÙ][a-zàèéìòù]+)+)/gi

9.4 Rilevamento supplier e tipo bolletta

// Fornitori noti
const SUPPLIERS = {
  ENEL:    /\b(?:enel|enel\s+energia|e\.on)\b/gi,
  ENI:     /\b(?:eni\s+gas|eni\s+e\s+luce|eni\s+plenitude)\b/gi,
  A2A:     /\bA2A\b/g,
  HERA:    /\bhera\b/gi,
  INPS:    /\bINPS\b/g,
};

// Tipo documento
const BILL_TYPES = {
  ELECTRICITY: /(?:fornitura\s+(?:di\s+)?energia\s+elettrica|kWh|kVA|POD)/gi,
  GAS:         /(?:fornitura\s+(?:di\s+)?gas\s+naturale|Smc|PDR|metano)/gi,
  WATER:       /(?:acquedotto|fornitura\s+idrica|servizio\s+idrico)/gi,
};

9.5 Metodi di pagamento

// Rilevamento metodi menzionati nella bolletta
const PAYMENT_PATTERNS = {
  DOMICILIATION: /(?:domiciliazione|addebito\s+diretto|SEPA|RID)\b/gi,
  BANK_TRANSFER: /(?:bonifico\s+bancario|IBAN|conto\s+corrente)\b/gi,
  BOLLETTINO:    /(?:bollettino\s+postale|MAV)\b/gi,
  APP:           /(?:app\s+(?:enel|eni)|sito\s+web|online)\b/gi,
  TOBACCONIST:   /(?:tabacchi|ricevitoria|lottomatica|sisal)\b/gi,
  POSTAL_OFFICE: /ufficio\s+postale\b/gi,
  ATM:           /(?:ATM|sportello\s+bancomat)\b/gi,
};
Nota: In caso di bassa confidenza (meno di 2 campi trovati), l'app mostra una nota: "Non ho trovato tutti i dati. Controlla il documento originale." con pulsante per visualizzare il testo grezzo estratto.

11.3 Considerazioni di sicurezza e privacy

  • Viene inviato solo il testo estratto (non PDF/immagine originale)
  • La chiave API Anthropic è configurata come variabile d'ambiente a build time (Angular environment)
  • Warning visibile all'utente prima dell'invio: "Il testo della tua bolletta sarà inviato a un servizio AI esterno"
  • Il testo inviato non include immagini, dati biometrici o informazioni non presenti nel testo
